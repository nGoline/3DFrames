# 3DFrames

**A picture frame for any artwork, printable on any bed.** Enter the size of the
thing you want to frame, pick a moulding, and get printable files — including
frames far larger than your printer, split into snap-together segments.

Free, open source, and entirely client-side: [**nGoline.github.io/3DFrames**](https://nGoline.github.io/3DFrames/)

There is no account, no upload, and no server. The geometry is generated in your
browser and the files never leave your machine.

---

## What it does

- **Any aperture size**, in inches or millimetres, with presets from 4 × 6 in to
  50 × 70 cm.
- **Seven shapes** — rectangle, square, circle, oval, arch, hexagon, octagon.
- **Ten edge profiles**, each a real parametric cross-section with an adjustable
  face width, thickness, rabbet and relief.
- **Nine face textures** cut into the surface as actual relief, so the grain or
  fluting survives into the print rather than being a render trick.
- **Captions** embossed or engraved into a rail, in any of four bundled faces.
- **Fittings**: backing panel, spring retainer bars, keyhole hanger, desk stands.
- **Automatic splitting.** Anything larger than your bed is cut into segments at
  the mitres, joined by printed butterfly keys with an adjustable fit clearance.
- **Exports** to per-part STL, a combined STL, a colour-coded 3MF at true scale,
  or a ZIP with all of it plus a printing and assembly guide.

## How it works

The interesting part is that nothing here needs mesh repair. Every solid is
built to be watertight from the start.

**Sweeping.** A frame is defined by its *opening path* — the closed outline of
the aperture — and a *cross-section* in `(u, v)` coordinates, where `u` runs
outward from the sight edge and `v` upward from the bed. The moulding is
generated by offsetting the path outward along per-vertex mitre bisectors and
sweeping the section around it:

```
P[j][i] = path[j] + bisector[j] · mitreScale[j] · u[i]   (x, y)
                                                  v[i]   (z)
```

One formulation covers everything: on a rectangle it produces exact 45° mitres,
on any convex polygon the correct shallower mitre, and along a sampled circle a
true parallel offset. Because a closed frame is topologically a torus, the
surface needs no end caps at all — it comes out manifold by construction. The
[smoke test](scripts/smoke.ts) checks this against an analytic volume:

```
volume = (2W + 2H)·A + 8·A·ū
```

for a flat rectangular moulding, and it agrees to within 1 part in 10⁴.

**Splitting.** Seams are placed at the frame's own mitres first, since a corner
is where a joint is least visible and the material is thickest. Runs that are
still too long are bisected until every piece fits. "Does it fit" uses the exact
rectangle-in-rectangle test at arbitrary rotation, which is what lets a 290 mm
rail sit corner-to-corner on a 256 mm bed.

**Joints.** At each seam, the largest axis-aligned rectangle that actually fits
inside the cut face is found by rasterising the section and running a
largest-rectangle-in-histogram scan. The pocket is sized from that, so it stays
buried in solid material whatever the profile looks like. The key itself is a
butterfly: wide at both ends, pinched at the waist, so it resists the only force
a picture frame joint really carries — the two segments pulling apart.

**Booleans.** Pockets, engraving and the keyhole plate go through
[Manifold](https://github.com/elalish/manifold), which guarantees a closed,
self-intersection-free result. That is the difference between an STL a slicer
accepts and one it silently mangles.

## Running it locally

```bash
git clone https://github.com/nGoline/3DFrames.git
cd 3DFrames
npm install
npm run dev
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server at `localhost:5173/3DFrames/` |
| `npm run build` | Production build into `dist/` |
| `npm run smoke` | Geometry checks — every shape × profile must come out a valid solid |
| `npx tsc -b` | Type check |

The geometry core has no browser dependencies: `npm run smoke` runs the whole
pipeline under plain Node, including splitting, joints, text and the exporters.
The WASM kernel and font files are injected by the host, which is what makes
that possible.

### Deploying your own copy

Fork it, enable Pages with **Source: GitHub Actions**, and push. The workflow in
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) runs the checks
and publishes `dist/`.

If your repository is not called `3DFrames`, change `base` in
[`vite.config.ts`](vite.config.ts) to match, or set `BASE_PATH=/` for a
user or organisation site.

## Layout

```
src/core/           geometry, no DOM and no browser APIs
  profiles.ts       the ten cross-sections
  shapes.ts         opening paths, mitre frames, path offsetting
  frame.ts          the pipeline: sweep → split → pocket → text → fittings
  geometry/
    sweep.ts        the offset sweep
    split.ts        where to cut so every piece fits the bed
    joints.ts       butterfly keys and their pockets
    facePattern.ts  surface relief as a height field
    packing.ts      convex hull, min-area rect, rect-in-rect fit
  export/           STL, 3MF, ZIP bundle
src/ui/             React panel, three.js viewport, bed arrangement
scripts/smoke.ts    the geometry test suite
```

## Printing notes

Print every part exactly as exported — flat on the bed, decorative face up. No
supports. Three perimeters and 15% infill is plenty for the frame; give the snap
keys four or more, since they carry the whole joint. If the keys are tight,
scale them down about 1%; if loose, scale up, or raise the joint clearance and
regenerate.

## Contributing

Issues and pull requests are welcome. If you touch the geometry, `npm run smoke`
has to stay green — and please add a check for whatever you changed. New edge
profiles are the easiest place to start: a profile is one function returning the
silhouette from the back outer corner round to the sight edge, and the rabbet
and back face are added for you. See [`src/core/profiles.ts`](src/core/profiles.ts).
